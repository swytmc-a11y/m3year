# معيار — تطبيق الجوال (Expo / React Native)

تطبيق جوال أصلي (iOS/Android) لمنصة معيار، مبني بـ **Expo SDK 57 + React Native
+ expo-router + TypeScript**. يستخدم **نفس قاعدة بيانات Supabase** التي يستخدمها
تطبيق الويب (نفس الجداول وسياسات RLS ومنطق المراجعة).

> **حالة المشروع:** الأساس + الإعلانات (تصفّح/تفاصيل/إعلاناتي/إنشاء وتعديل) +
> طلب التوثيق المالي ومتابعة حالته + **الرسائل الداخلية مع إشعارات Push
> حقيقية**. **تدفق المحاسب والإدارة يبقى على تطبيق الويب** (قرار تصميم:
> العمليات التشغيلية على الويب، تجربة المستهلك على الجوال). بقية الوحدات
> (التقييمات...) تُبنى تباعًا.

## التشغيل محليًا

```bash
cd mobile
npm install
cp .env.example .env   # ثم املأ قيم Supabase
npx expo start
```

ثم:
- امسح رمز QR بتطبيق **Expo Go** على جوالك (Android/iOS) لتشغيله على الجهاز، أو
- اضغط `a` لمحاكي Android / `i` لمحاكي iOS، أو
- اضغط `w` لفتح نسخة الويب (تحتاج `react-native-web` و`react-dom` — مثبّتة كـ
  devDependencies).

## متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | مفتاح anon العام |

(البادئة `EXPO_PUBLIC_` تجعل القيمة متاحة داخل التطبيق.)

## الرسائل والإشعارات (المرحلة ٥)

- **المحادثات:** الممول يبدأ محادثة من صفحة تفاصيل إعلان منشور (زر «تواصل مع
  صاحب المشروع»)؛ محادثة واحدة فقط لكل ممول/إعلان (قيد فريد في قاعدة
  البيانات). الرسائل تُحدَّث لحظيًا عبر **Supabase Realtime** أثناء فتح
  المحادثة.
- **إشعارات Push حقيقية (تصل حتى والتطبيق مغلق):**
  - عند إرسال رسالة، يستدعي التطبيق مباشرة Edge Function باسم
    `notify-new-message` بجلسة المُرسِل (وليس عبر محفّز قاعدة بيانات، لتفادي
    الحاجة لتخزين سرّ في قاعدة البيانات). الدالة تتحقق عبر RLS أن المُرسِل
    فعلاً طرف في المحادثة، ثم تُرسل عبر Expo Push API لرموز جهاز المستلم.
  - **يتطلب تسجيل رمز EAS** (`eas init`) — بدونه، تسجيل رمز الجهاز (push
    token) يُتخطّى بصمت (لا يوقف التطبيق) لأن `getExpoPushTokenAsync` يحتاج
    `projectId`. شغّل `eas init` مرة واحدة قبل اختبار الإشعارات فعليًا.
  - **إشعارات Push لا تعمل في Expo Go بعد** لبعض إصدارات SDK على Android —
    الطريقة الموثوقة للاختبار الفعلي هي بناء تطبيق تطويري
    (`eas build --profile development`).
  - عند النقر على الإشعار، يفتح التطبيق المحادثة المعنية مباشرة (معالجة في
    `app/_layout.tsx`).

## ملاحظات

- **تسجيل الدخول عبر الجوال (OTP)** يحتاج تفعيل مزوّد SMS في Supabase (نفس شرط
  الويب). حتى ذلك الحين استخدم **الدخول التجريبي** (`/demo`) للمعاينة.
- **RTL**: مُفعّل عبر `I18nManager.forceRTL`. عند أول تشغيل على جهاز حقيقي قد
  يحتاج إعادة تحميل واحدة ليأخذ اتجاه RTL مفعوله بالكامل.
- الخطوط (Almarai / IBM Plex Sans Arabic / IBM Plex Mono) تُحمّل عبر
  `@expo-google-fonts` وتُضمّن في التطبيق (لا تحتاج إنترنت وقت التشغيل).
- إشعارات Push **غير مدعومة على هدف الويب** (`expo start --web`) —
  الأكواد المرتبطة بها محمية بفحص `Platform.OS !== "web"` فلا تُسبب أعطالًا،
  لكنها ببساطة لا تعمل هناك (متوقع؛ الويب ليس المنصة المستهدفة لها).
